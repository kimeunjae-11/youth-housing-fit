# GitHub에 올리는 순서

이 압축을 풀면 backend/, data/, docs/가 나옵니다. 팀 저장소의 같은 위치에 추가하세요. frontend/와 design/는 건드릴 필요 없습니다. 기존 같은 이름 파일이 있으면 덮어쓰기 전에 변경 내용을 비교하세요. 루트 .gitignore는 기존 파일을 교체하지 말고 필요한 줄만 합치세요.

1. 팀 저장소의 현재 main을 내려받고 작업 브랜치 feat/judge-api로 이동합니다. 이미 같은 브랜치가 있으면 그 브랜치를 사용합니다.
2. 압축의 backend/, data/, docs/ 파일을 팀 저장소 루트에 넣습니다.
3. backend 폴더에서 README의 테스트를 실행합니다.
4. 변경 파일을 확인하고 해당 파일만 커밋합니다. .env, 개인정보, 가상환경은 올리지 않습니다. .env.example은 공개 가능한 설정 예시입니다.
5. 작업 브랜치를 push하고 main을 대상으로 PR을 만듭니다.
6. 팀 규칙대로 다른 팀원 1명 이상 확인 후 머지합니다. main에 직접 push하지 않습니다.

이번 파일은 신규 기능이므로 커밋 예시는 `feat: 행복주택 자격 사전판정 및 추천 API 구현`입니다. 팀 문서의 ‘오늘 이후 fix PR만’이 적용되는 시점이라면, 이 신규 기능을 fix로 위장하지 말고 팀과 개발 마감 범위를 확인하세요.

저장소 주소가 없어 여기서 git push/PR 생성은 하지 않았습니다. 사용자 본인이 업로드하도록 파일만 준비했습니다.

## PR 본문 예시

행복주택 청년 기준을 JSON에서 읽어 검사한 기본조건과 추가 확인 항목을 분리합니다. 참고용 주택 탐색은 자격 판정과 별개로 지역·월세에 맞는 목록을 반환하며 접수 마감 상태를 표시합니다. 엑셀 출처와 데이터 기준일을 함께 보관합니다.

전체 공고 자격 검증은 남아 있으며 기본조건 통과를 신청 가능으로 표시하지 않습니다. 마감 공고는 참고용 탐색에만 포함합니다. 프론트 연결과 공개 배포는 아직 하지 않았습니다.

검증: backend의 unittest 11개 통과. 모집·가격·지역 필터는 명시적인 가상 테스트 공고로 확인했습니다.
